# Drawdown Tracker

Computes the **drawdown** of a daily price series (how far the price sits below its running peak) and plots it, highlighting the **maximum drawdown**: the worst peak-to-trough loss over the period.

Maximum drawdown complements volatility as a risk measure: volatility tells you how much a price wiggles, drawdown tells you how much an investor could actually have lost, and for how long.

## Setup

Requires **Python 3.11+** and Git.

```bash
git clone https://github.com/<your-username>/drawdown-tracker.git
cd drawdown-tracker
python -m venv .venv
source .venv/bin/activate          # Windows (Git Bash): source .venv/Scripts/activate
pip install -r requirements.txt
```

Check the prompt shows `(.venv)` before installing anything.

## Usage

From the repo root:

```bash
python src/analysis.py
```

Paths are resolved from the repo root, so the script also works when launched from another folder. To run it on a different file:

```bash
python src/analysis.py --input path/to/other.csv --output outputs/other_plot.png
```

Expected console output with the sample data:

```
Rows analysed : 252 (2025-01-14 -> 2025-12-31)
Total return  : +9.92%
Max drawdown  : -12.81%  (peak 2025-02-19, trough 2025-05-02, recovery 2025-06-11)
Saved plot    : .../outputs/plot.png
Saved metrics : .../outputs/drawdown.csv
```

### Outputs

| File | Content |
|---|---|
| `outputs/plot.png` | Top: close vs running peak, with the max-drawdown episode shaded. Bottom: "underwater" drawdown chart with the trough annotated. |
| `outputs/drawdown.csv` | Per-day `daily_return`, `cum_return`, `running_peak`, `drawdown`. |

`outputs/` is git-ignored: everything in it is regenerated by running the script.

## Method

For closing prices $P_t$:

- Running peak: $M_t = \max_{s \le t} P_s$
- Drawdown: $DD_t = P_t / M_t - 1$ (always $\le 0$)
- Maximum drawdown: $\min_t DD_t$

The script also reports the dates of the peak, the trough and the recovery (first close back at or above the old peak, or "not recovered").

## Input data

`data/raw/prices.csv` is a small sample (252 trading days of 2025) committed so the repo runs straight after cloning. Any CSV with these two columns works:

| column | type | example |
|---|---|---|
| `date` | ISO date | `2025-01-14` |
| `close` | positive float | `99.11` |

The loader sorts by date, drops empty rows and duplicate dates, and stops with a clear error if a column is missing or a price is not positive. Larger or licensed datasets should be placed in `data/raw/` locally: everything there except the sample is git-ignored.
